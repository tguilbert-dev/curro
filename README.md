# Curro

An offline-first running tracker, installable as a PWA. It imports training plans written against a public JSON Schema (typically generated by an AI chatbot), then tracks your runs against the plan with common running heuristics.

- **Today**: race countdown, today's workout, training warnings, one-tap check-off of other activities
- **Calendar**: week view (planned vs actual per day, collapsible training checks) and month view (run icons and colours, cross-training badges, weekly totals). Swipe to change week/month; tap a day to log, tick cross-training, or nudge its planned workout a day earlier/later
- **Progress**: weekly volume chart (actual vs planned) with a table view
- **Cross**: your own list of non-running activities (PT, boxing, rowing…), each a daily yes/no, with a swipeable weekly grid and 12-week days-per-week trends
- **Plan**: import a plan (file or paste), build an AI prompt, **review & adjust** (export recent training vs the plan, optionally with cross-training, as a prompt; paste the reply back to see week-by-week changes and apply), archive of previous plans
- **Settings**: km/mi, week start (Monday/Sunday), theme, backup/restore

Runs are colour-coded by category (easy = green, long = blue, hard = orange; races get a flag icon), with an icon per workout type. The weekly chart stacks easy/long/hard so the 80/20 balance is visible at a glance.

All data stays on the device (IndexedDB). There are no accounts and no server.

Checks only appear when they have something to say (e.g. no 10% warning when you're following your plan's own step-up).

New versions are offered with a "Reload" bar rather than applied mid-use, so an update never interrupts a half-typed entry.

## Training checks

| Check | Rule |
|---|---|
| 10% rule | Weekly distance ≤ 110% of the previous week (returning from a cutback week is allowed) |
| Long run share | Longest run ≤ 50% of the week's distance |
| 80/20 | ≥ ~80% of distance at easy effort (easy, recovery, long) |
| Hard sessions | ≤ 2 per week, not on consecutive days |
| Rest day | ≥ 1 per week |
| Long run progression | ≤ ~15% beyond the longest run of the previous 4 weeks |
| Acute:chronic load | Last 7 days ÷ 4-week weekly average; 0.8–1.3 is good, > 1.5 is a spike |
| Easy pace | Easy runs no faster than the plan's `paces.easy` (or close to recent hard-session pace) |
| Taper | ~85% / 70% / 50% of peak volume in the last three weeks |
| Plan vs actual | Share of planned distance run so far; missed long/quality sessions |

The same 10% and 50% rules are applied to a plan when you import it, so a bad AI-generated plan is flagged before you use it.

## The plan schema

[`schema/curro-plan.v1.schema.json`](schema/curro-plan.v1.schema.json) (JSON Schema 2020-12, `$id: urn:curro:plan:v1`). When deployed it is published at `<site>/schema/curro-plan.v1.schema.json`.

Plans are **weeks of weekdays, not dates**. The last week in `weeks` is race week (the Monday–Sunday week containing `race.date`), and earlier weeks count backwards from it. LLMs get calendar arithmetic wrong often; this format avoids it entirely.

```json
{
  "schemaVersion": 1,
  "name": "12-week half marathon",
  "units": "km",
  "race": { "name": "City Half", "date": "2026-12-20", "distance": 21.1, "goalTime": "1:54:59" },
  "paces": { "easy": "6:15", "race": "5:25" },
  "weeks": [
    { "focus": "Base", "days": [
      { "day": "tue", "type": "easy", "distance": 5, "title": "Easy run" },
      { "day": "sun", "type": "long", "distance": 9, "title": "Long run" }
    ] }
  ]
}
```

Workout types: `easy`, `recovery`, `long` (easy) · `tempo`, `intervals`, `hills`, `fartlek`, `progression`, `race-pace`, `time-trial`, `race` (hard) · `cross-training`, `rest`.

A full example is in [`examples/half-marathon-12-weeks.json`](examples/half-marathon-12-weeks.json). The app's **Plan → Get a plan from an AI chatbot** section builds a ready-to-paste prompt that includes the schema and coaching rules.

Workflow: fill in the form → copy prompt → paste into a chatbot → email the JSON to yourself → open Curro on your phone → **Plan → Choose file**. The importer strips code fences and chatter around the JSON and lists readable validation errors to paste back to the chatbot.

## Development

```sh
npm install
npm run dev        # http://localhost:5173
npm test           # unit tests for dates, plan import and heuristics
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/
```

Stack: React 19, TypeScript, Vite, vite-plugin-pwa, Dexie (IndexedDB), Ajv (schema validation).

```
schema/            public plan schema (source of truth; emitted into dist/schema/)
examples/          example plan
src/lib/           pure logic: dates, units, plan import, stats, heuristics, prompt, activities
src/views/         one component per tab
src/components/    shared UI: run form, day detail, chart, check list
src/db.ts          Dexie database and hooks
```

## Deploying to GitHub Pages

`.github/workflows/deploy.yml` runs the tests, builds, and publishes `dist/` on every push to `main`.

1. Create an empty repository on GitHub (no README or licence, so the first push is clean).
2. Push this project to it:
   ```sh
   git branch -M main
   git add .
   git commit -m "Initial version of Curro"
   git remote add origin https://github.com/<you>/curro.git
   git push -u origin main
   ```
3. On GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Watch the run under the **Actions** tab. The site will be at `https://<you>.github.io/curro/` and the schema at `https://<you>.github.io/curro/schema/curro-plan.v1.schema.json`.

The build uses a relative base path and hash routing, so it works under any sub-path (or a custom domain) without changes. Any other static host works too: serve `dist/` over HTTPS.

## Data safety

Browsers can evict site data. Curro asks for persistent storage, and on iOS installing to the Home Screen keeps Safari from clearing it. Use **Settings → Download backup** regularly; backups restore on any device.
